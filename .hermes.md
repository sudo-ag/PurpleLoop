# Purpleloop — Hermes cockpit

Hermes running inside this repo can drive the purple-team CTF simulator
around the existing Ollama agents. The agents themselves are untouched;
Hermes handles start / watch / read-report / restart through `src.ops`.

See `src/ops.py` for the programmatic verbs Hermes can call, and the
shell equivalents below. The dashboard is disabled by default to keep the
Ollama loop focused; use `--dashboard` only when you explicitly want the
FastAPI UI.

## Quick verbs (Hermes natural language → action)

| You say                                      | What happens                                                       |
|----------------------------------------------|--------------------------------------------------------------------|
| "start a mock simulation"                    | `uv run python -m src.ops start --host mock` (background, no UI)  |
| "start a simulation against my target"       | `TARGET_HOST=... uv run python -m src.ops start --host ...`       |
| "watch until the sim ends"                   | poll `simulation.log`, then read the report                       |
| "read the battle report"                     | read `battle_report.md` (trimmed if long)                         |
| "restart with model llama3.1"               | kill won't be attempted; relaunch with `--model llama3.1`         |
| "start with the dashboard"                   | add `--dashboard` to `start` or `run`                             |

## Shell equivalents (so you don't need Hermes for one-offs)

```bash
# From the repo root (uv is the project runner):

# Start a mock run in the background (prints pid + log path)
uv run python -m src.ops start --host mock

# Start a mock run with a different model
uv run python -m src.ops start --host mock --model llama3.1

# Read the battle report (if it exists)
uv run python -m src.ops report

# Watch until the sim ends or 20 minutes pass
uv run python -m src.ops watch
uv run python -m src.ops watch --max-minutes 60 --interval 10

# Run and watch in one command
uv run python -m src.ops run --host mock --max-minutes 30

# Optional UI path
uv run python -m src.ops run --host mock --dashboard
```

## How the cockpit pieces fit together

- `src.ops` is the Hermes-facing entrypoint. It launches `main.py` with
  the right env vars and defaults to `DISABLE_DASHBOARD=1`.
- `main.py` owns the core run: executor, agents, orchestrator, report write.
- With the dashboard disabled, `watch` polls `simulation.log` for progress.
- If `--dashboard` is used, `main.py` starts the FastAPI UI, the
  orchestrator pushes `POST /update`, and `GET /state` becomes available.
- When the sim ends, `main.py` writes `battle_report.md`; Hermes reads
  that file directly.
- Env vars: `TARGET_HOST` (default `192.168.64.10`; `mock` for the fake
  executor), `TARGET_USER`, `TARGET_PWD`, `MODEL` (default
  `llama3.2:latest`), `DISABLE_DASHBOARD` (default `1`), and
  `DASHBOARD_URL` (default `http://localhost:8000`, only used with UI).

## Notes / caveats

- There is no clean "kill the sim now" verb. `ops.py` launches `main.py`
  and doesn't poke at PIDs after that. For most turns, "start a new one"
  is the realistic operation.
- `ops.py` runs `main.py` via `sys.executable` / the venv python so it
  picks up project deps automatically; `target_host=mock` hits the
  `MockExecutor` and needs no real target.
- The dashboard `/state` snapshot keeps up to 80 events when the UI is
  enabled; older ones drop.
- The orchestrator's `run_simulation` already saves `battle_report.md`
  and prints the winner to stdout, which flows into `simulation.log`
  when run via `ops.py start`.
